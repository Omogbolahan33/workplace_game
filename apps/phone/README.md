# LEDGER on a phone — the store build

The same `index.html`, in a native shell. Capacitor wraps the single file that
already exists: the web directory (`www/`) is filled by `tools/mobile.mjs` at
build time and is byte-identical to the folder the zip is made from, so the app
on a phone and the file on a laptop are the same game, offline in both.

This path is here because it is the honest answer to "a real app on my phone":
the game is one HTML file with no external requests, so a native shell gives it
an icon, a splash screen, a share sheet, a status bar, and a store listing —
without a second implementation of thirty screens to keep in step. Every
dependency in `package.json` is one the config uses: the `phone` gate fails on a
plugin that is declared and never configured, so this file cannot drift back into
wishful listing. React Native is the other path, and it is being prepared from the other end: see
`apps/mobile` and the `rn` gate, where the simulation runs on a native host.

## What is here

```
capacitor.config.json   appId, app name, dark colours, the two plugins' settings
www/                    the built game — written by tools/mobile.mjs, never by hand
resources/              the app's face: masters drawn from ledger/icon.svg
android/                generated by `cap add android` (gitignored) — incl. the faces
package.json            the shell and the two plugins it actually configures
```

## Building it

The platform folders are generated, not committed: they are large, they are
regenerable, and a project that cannot be built in the repository it lives in is
a project with a lie in it. Run these where the SDK is:

```bash
npm install                       # in apps/phone
npx cap add android               # once per platform: writes android/
npx cap add ios                   # (macOS, with Xcode)
npm run sync                      # copies www/ in, updates the native projects
npm run open:android              # Android Studio; then build/sign as usual
```

`npm run sync` at the repository root does the same, since `tools/mobile.mjs`
has already put the current build in `www/`.

`android/`, `ios/` and `node_modules/` are gitignored. If a platform folder ever
*is* committed, this file should say so and the `phone` gate will check the
synced copy against the build.

## The app's face

`npx cap add android` writes a template, and a template has its own icon: a
light-blue cross on a white plate, at all five densities, round and adaptive, plus
a white splash screen. Every dimension correct, every picture somebody else's —
and it shipped that way until the `phone` gate learned to ask what an icon *is*
rather than what it is called.

`npm run assets` (which `tools/rebuild.sh` runs) draws every icon and splash from
**`ledger/icon.svg`** — the same file the PWA icons, the favicon and the zip carry
— and the background from `capacitor.config.json`. One drawing, one colour, and no
picture invented here:

| written | what |
|---|---|
| `resources/` | masters: 1024px icon, adaptive foreground + background, 2732px splash (light and dark). Committed, because they are what a store listing wants and what a fresh `cap add` needs |
| `android/…/mipmap-*` | launcher, round and adaptive-foreground at 48/72/96/144/192px |
| `android/…/drawable-*` | the splash set, portrait and landscape, at five densities |
| `values/ic_launcher_background.xml` | the adaptive plate colour — `#080b10`, not the template's white |

The gate compares **pixels**, not filenames: every native icon is decoded and
matched cell by cell against the web icon rendered from the same SVG. The game's
mark sits 2.5–8.6 away at every size; the template's cross sat at 153.9. Put one
template icon back and the gate says so, by name and by distance.

## What the shell adds

| | |
|---|---|
| **offline** | the game is in the bundle; the `sw.js` in `www/` is unused here, because a WebView does not need a service worker to open a local file |
| **splash + status bar** | dark, no spinner, the title bar hidden — configured in `capacitor.config.json`, not improvised in the page. These two plugins *are* installed and synced (`@capacitor/splash-screen`, `@capacitor/status-bar`) |
| **share** | not a plugin: the game copies invite links and codes with `navigator.clipboard` (it never calls `navigator.share`), and that works in a WebView. A native share sheet would need a call from inside the payload, which is the one thing this build keeps byte-identical to the zip — so it is left out rather than half-wired |
| **back button** | the game closes an open modal on Escape; the system back button is Android's default, which walks the WebView's history and then leaves the app. The save is written as the game goes, and booting hydrates it, so leaving costs a player nothing mid-quarter — but an in-app back that stepped the game back a screen would need the same payload hook |
| **App Store** | `appId com.ledger.game`, an icon set and a splash from the same drawings the PWA uses |
